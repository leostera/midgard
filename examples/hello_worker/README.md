# HelloWorker

Two local modules (`HelloWorker` and `HelloWorker.Greeter`) plus the pure-Elixir Jason dependency demonstrate compiled BEAM packaging. `use Midgard.Worker` exports the binary `__midgard_call__/1` wrapper around `handle_request(%Midgard.Request{})`. Request handling and wrapper tests run on ordinary OTP, **not** in libbeam.

```sh
mix deps.get
mix test
mix midgard.build                   # uses midgard.config.exs
mix packer.pack                     # uses packer: [entry: HelloWorker] in mix.exs
mix packer.inspect hello_worker.midgard
mix packer.inspect hello_worker.midgard --target current-core  # expected refusal
```

The inspectable `hello_worker.midgard/` contains `manifest.json`, exact-name local BEAMs, Jason BEAMs and the Midgard SDK BEAMs; each module is hashed and assigned to a dependency/application. The entrypoint is `Elixir.HelloWorker:__midgard_call__/1`, protocol `midgard.bytes.v1`. The manifest states `execution: not_verified`. The pinned static current-core diagnostic **fails for this example**; neither command deploys or starts an Isolate. A structurally valid artifact is not proof of whole-group libbeam admission or tenant isolation.

Routes handled in ordinary OTP tests: `GET /hello?name=...`, `POST /json`, `POST /echo` (binary), and 404 for unknown requests. This source-tree example uses local checkout paths in `mix.exs`; projects generated by the published CLI use Hex packages.
